# specs-db

数据库设计：根据业务描述与原型稿设计数据层，输出建库脚本/结构。

## 前置依赖（先检查，缺失就停）

- 必须存在：`docs/product/business-flow.md`、`docs/product/demo/`（≥1 个 HTML 页面）。
- 建议存在：`docs/product/glossary.md`（字段名优先用其中的英文；缺失则用合理英文名并提醒用户）。
- 缺失必选项时，提示先运行对应 skill（product-business / demo / product-glossary），然后结束，不空跑。

## Step 1 — 选 DB 类型（你来推荐）

先读 `docs/product/sense.md`、`docs/product/business-flow.md`，了解产品形态与数据特征。用 AskUserQuestion 让用户选择 DB，**给出你的推荐理由**，把推荐项放在首位：

| DB | 适合场景 | 推荐倾向 |
| --- | --- | --- |
| MySQL | 常见业务系统、关系模型、需要事务与通用生态 | 默认推荐 |
| SQLite | 简单/单机/原型/嵌入式，文件即库 | 轻量场景推荐 |
| PostgreSQL | 复杂查询、高并发、JSON/地理等高级特性 | 有需要时 |
| MongoDB | 文档型、schema 灵活、内容类产品 | 视数据特征 |

选项包含"其他（自定义）"。若用户难以决定，按产品数据特征推荐一个并说明理由。

## Step 2 — 按所选 DB 生成数据设计

读 `docs/product/business-flow.md` 的业务描述 + `docs/product/demo/` 页面 + `docs/product/glossary.md`（字段英文名优先），按所选 DB 语法输出。

- 输出目录：`mkdir -p docs/specs/data`。
- 目标文件已存在时，问用户：覆盖 / 备份后替换 / 另存。

### MySQL 模板（默认，9 条硬性要求）

根据 business-flow.md 业务描述，阅读 demo 里的页面，实现数据库设计（字段名优先使用 glossary.md 里的英文），必须使用标准 MySQL 支持的语法，输出至 `docs/specs/data/table.sql`，遵循：

1. **禁用保留字**：表名、字段名不能是 MySQL 保留字。
2. **不用外键**：不使用 FOREIGN KEY。
3. **自增 ID 主键**：除关联表外，尽量用 `id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY`；关联表用联合主键。
4. **字符集 utf8mb4**：表与库统一 `DEFAULT CHARSET=utf8mb4`。
5. **注释清晰**：表注释、字段注释都用 `COMMENT`。
6. **枚举用 varchar**：枚举值用 `VARCHAR` 并定义好长度。
7. **int/bigint 定义长度且非负**：如 `INT(11)`/`BIGINT(20)`，使用 `UNSIGNED`。
8. **尽量不用 NULL**：用 `NOT NULL` + 默认值（空串/0）。
9. **不用 ON UPDATE**：不使用 `ON UPDATE CURRENT_TIMESTAMP` 等类似功能。

### 其他 DB 适配（每条完整列出，不省略）

将 MySQL 的 9 条要求**逐条翻译**为该 DB 方言，输出到同一目录 `docs/specs/data/`，文件名按 DB 类型。

#### SQLite → `docs/specs/data/table.sql`（SQLite 方言）

1. **禁用保留字**：SQLite 保留字（如 `ORDER`、`GROUP`、`INDEX`、`LIMIT`、`CONFLICT`、`NULL` 等）不得作表名/字段名。
2. **无外键**：不使用 FOREIGN KEY。
3. **自增主键**：`id INTEGER PRIMARY KEY AUTOINCREMENT`；关联表用联合主键。
4. **字符集**：SQLite 原生 UTF-8，不写 CHARSET。
5. **注释清晰**：建表语句用 `--` 注释说明表/字段用途（SQLite 无 COMMENT 语法）。
6. **枚举用 TEXT/VARCHAR**：枚举值用 `TEXT` 或 `VARCHAR(n)`，可用 `CHECK(col IN (...))` 限制。
7. **整数非负**：SQLite 无 UNSIGNED 与显示宽度——用 `INTEGER`/`BIGINT`，非负用 `CHECK(col >= 0)`。
8. **少用 NULL**：`NOT NULL` + 默认值（空串/0）。
9. **不用 ON UPDATE**。

#### PostgreSQL → `docs/specs/data/table.sql`（PG 方言）

1. **禁用保留字**：PG 保留字不得作表名/字段名（不使用双引号绕开）。
2. **无外键**：不使用 FOREIGN KEY。
3. **自增主键**：`BIGSERIAL PRIMARY KEY`（或 `GENERATED BY DEFAULT AS IDENTITY`）；关联表用联合主键。
4. **字符集**：库级 UTF8（`CREATE DATABASE ... ENCODING 'UTF8'`），表无需声明。
5. **注释清晰**：`COMMENT ON TABLE` / `COMMENT ON COLUMN`。
6. **枚举用 VARCHAR**：枚举值用 `VARCHAR(n)`，可配合 `CHECK`。
7. **整数非负**：PG 无 UNSIGNED、无显示宽度——用 `INTEGER`/`BIGINT`，非负用 `CHECK(col >= 0)`。
8. **少用 NULL**：`NOT NULL` + 默认值。
9. **不用 ON UPDATE**。

#### MongoDB → `docs/specs/data/schema.json`（文档模型，无建表 SQL）

1. **字段名避开特殊字符**：不用 `$` 开头、字段名不含 `.`（MongoDB 约束）。
2. **无外键**：引用关系用 `ObjectId` 字段约定，不加引用约束。
3. **主键**：`_id` 由 MongoDB 自动生成，无需手动定义。
4. **字符集**：BSON 字符串原生 UTF-8，无声明。
5. **说明清晰**：每个 collection / 字段在 schema.json 里带 `"description"` 说明。
6. **枚举**：`"type": "string"` + `"enum": [...]`（或 description 注明允许值）。
7. **数值**：`int32`/`int64`/`double`；非负用 description 或应用层约定说明。
8. **少用 NULL**：可选字段说明缺省行为，倾向用默认值。
9. **无 ON UPDATE**：时间字段（created_at/updated_at 等）由应用写入。
