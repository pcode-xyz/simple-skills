# demo

两步流程：先"问"清楚产品（产出产品思考锚点 `docs/product/sense.md`），再"做"一组风格化 HTML demo 页面（产出 `docs/product/demo/`）。

## 核心规则（grilling 模式）

- **一问一答**：一次只问一个问题，等用户回答后再继续。不要一次抛多个问题。
- **每问附推荐答案**：给出你的建议，帮用户快速做决定。
- **事实靠查、决策靠问**：能从环境查到的（文件系统、已有文档等）先查再问；需要用户拍板的决策，逐个问。
- **达成共识前不写文件**：sense.md 和 demo 都在用户确认后再生成。
- **用户答不上来时**：基于已收集的上下文给出你的推荐假设，标注"（假设）"，继续往下走。

## Phase 1 — 摸清产品（grill）

### 1.1 问平台类型（AskUserQuestion，单选）

- web / H5 / 小程序 / 手机App / 客户端软件

记录选择，后续文案与页面语气据此微调。

### 1.2 逐个追问产品问题

按顺序一问一答，每个问题给出推荐答案，等用户回答/修正后再进入下一个。可对模糊回答追问澄清。

1. **产品品类**：你想做的是哪个类型的产品？（如笔记工具、记账、社交、效率工具……）
2. **竞品**：市面上相似的产品有哪些？它们各自怎样？
3. **差异点**：你希望做到不一样的是什么？
4. **产品理念**：你的产品理念是什么？（产品存在的理由、核心主张）
5. **用户痛点**：你观察到的目标用户痛点是什么？
6. **要解决的问题**：你希望解决的核心问题是什么？（收敛成一句清晰的问题陈述）
7. **解决方案**：打算如何解决这个问题？（方案概览即可，不需细节）
8. **核心主脉络（28 定律）**：这个产品最核心的主脉络是什么？基于 28 定律，承载 80% 价值的 20% 核心功能是哪部分？主脉络 = 用户从进入到获得价值最常走的那条路径。

若环境里已有相关材料（如旧的 sense.md、调研文档），先读再问，不重复提问。

### 1.3 确认并生成 sense.md

- 把收敛结果整理成一份简明摘要，先给用户确认；确认后写入 `docs/product/sense.md`。
- 若文件已存在，问用户：覆盖 / 备份旧文件后替换 / 保留旧文件另存新文件。
- `mkdir -p docs/product`（不依赖 init-docs 已跑过）。
- 产品名：若 grill 过程未提及，先问一个工作名。

模板（缺失项标注"待定"）：

    # <产品名> 产品思考锚点

    ## 一、产品形态
    - 平台：web / h5 / 小程序 / 手机app / 客户端（择一）
    - 一句话定位：<一句话说清这是什么产品>

    ## 二、产品品类
    <属于什么类型的产品>

    ## 三、竞品分析
    <市面上相似的产品 + 各自优劣>

    ## 四、差异点
    <要做得不一样的地方>

    ## 五、产品理念
    <核心理念 + 一句说明>

    ## 六、用户痛点
    <目标用户痛点>

    ## 七、要解决的问题
    <收敛成一句清晰的问题陈述>

    ## 八、解决方案
    <如何解决，方案概览>

## Phase 2 — 风格化 demo

### 2.1 问风格（AskUserQuestion，单选）

- 简约现代 / 毛玻璃 / 高级感 / 其他（用户自定义描述）

### 2.2 先定设计风格（CSS 设计令牌）

动手写页面**之前**，先在 `css/style.css` 里把设计风格约定成**设计令牌**与**共享组件**，作为整套页面的样式基座；后续扩充页面统一从这里取，保证风格一致：

- **设计令牌**（`:root` CSS 自定义属性）：色板（主色/辅色/背景/文字/边框）、字体栈、字号阶梯、间距、圆角、阴影、描边。
- **共享组件类**：按钮、卡片、导航、标题区、栅格等。
- 风格映射（选"其他"时按用户描述自行推断）：
  - 简约现代：大量留白、中性色、单一强调色、细边框轻阴影、系统字体
  - 毛玻璃：`backdrop-filter` 磨砂、半透明面板、彩色渐变背景、圆角、柔和描边
  - 高级感：深色基调、衬线/优雅字体、暖色或金色点缀、克制排版

### 2.3 生成文件结构与页面

输出到 `docs/product/demo/`（`mkdir -p docs/product/demo/css docs/product/demo/js`）：

    docs/product/demo/
    ├── index.html       ← 对比页：用 iframe 同屏展示下面 3 页
    ├── page-01.html     ← 页面 1
    ├── page-02.html     ← 页面 2
    ├── page-03.html     ← 页面 3
    ├── css/style.css    ← 设计令牌 + 共享组件样式
    └── js/main.js       ← 共享交互（如需）

- **CSS / JS 独立文件**：每个 HTML 用 `<link rel="stylesheet" href="css/style.css">` 引入样式、`<script src="js/main.js">` 引入脚本，不内联样式与脚本。
- **3 个不一样的页面**：基于 sense.md 选 3 个最有代表性的页面，围绕"核心主脉络"重点呈现那 20% 核心功能。例如：首页（定位/卖点）、核心功能页（主脉络）、行动或详情页（价值/CTA）。页面自身差异优先用共享令牌/组件组合实现。
- **不加手机框/窗口框等设备 mockup**：只做普通响应式页面；屏幕尺寸由浏览器窗口直接控制模拟。
- 每个 HTML 头部留注释 `<!-- 由 /simple:demo 生成 -->`。

### 2.4 对比页

- `index.html` 用 iframe 把 3 个页面**同屏**并排展示，顶部一条简单说明栏（每页名 + 一句话），方便一屏对比。
- 对比页本身引用同一份 `css/style.css`，风格一致。

## 完成后

- 报告 `docs/product/sense.md` 与 `docs/product/demo/index.html` 路径，提示用户在浏览器打开对比页查看。
- 询问是否需要调整风格、增删页面或修改内容，可迭代。
