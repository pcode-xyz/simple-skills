# demo

两步流程：先"问"清楚产品（产出产品思考锚点 `docs/product/sense.md`），再"做"一组风格化 HTML demo 页面（产出 `docs/product/demo/`）。

**Phase 1（本文）与 Phase 2（`demo-html.md`）分开载入**：Phase 1 是纯对话推演，用不到 HTML 规则；Phase 1 确认后，再 Read `demo-html.md` 进入 HTML 生成。两部分上下文刻意不混用。

## 核心规则（grilling 模式）

- **一问一答**：一次只问一个问题，等用户回答后再继续。不要一次抛多个问题。
- **每问附推荐答案**：给出你的建议，帮用户快速做决定。
- **事实靠查、决策靠问**：能从环境查到的（文件系统、已有文档等）先查再问；需要用户拍板的决策，逐个问。
- **达成共识前不写文件**：sense.md 和 demo 都在用户确认后再生成。
- **用户答不上来时**：基于已收集的上下文给出你的推荐假设，标注"（假设）"，继续往下走。
- **关键决策不许静默悬空**：影响 demo 形态的次要决策（风格、细节取舍等），用户若答"不确定/纠结"，给推荐 + 理由、标"（假设）"作为工作结论继续，并在 sense.md「待确认」留档。**结构性决策（平台、核心形态）例外**：它们决定核心体验与竞争力，必须 push 到用户拍板的结果，不许用（假设）顶替带过。

## Phase 1 — 摸清产品（grill）

按**产品推演脉络**推进：先立题（值不值得做）→ 挖用户与问题（给谁、痛在哪）→ 定方案与本质（怎么做、是什么）→ 走旅程与落地（怎么用、在哪落地）→ 对照竞争与差异（凭什么）→ 立价值与愿景（相信什么、做多大）→ 验证商业与风险（怎么活、怎么死）。每一环收敛出结论再进下一环。

**结论循环（每环通用 6 步，能咬合的都用上）：**
1. **ask**：一次一问，附推荐答案。
2. **启发**：不只给答案，还开方向——举例子、给选项、抛思路，帮用户从"不知道"到"有的想"。
3. **对抗**：质疑答案——反例/边界、事实还是推断、和前面结论矛盾吗、凭什么。
4. **第一性原理**：剥离形态回到本质——用户真正要达成的 job 是什么、达成它的最短路径是什么、产品本质上是什么对象。
5. **联网搜索**：答案里可查证的事实点，用 WebSearch 验证（每环给了具体搜法）；查不到就明说"搜索受限，仅按用户认知记录"，不编造来源。
6. **验证**：结论标成【事实】/【假设】/【待定】，与之前环节交叉核对，冲突当场对齐。

标不出【事实】的至少给出带理由的【假设】；所有结论落盘 sense.md 对应章节。

### 1.1 立题 · 前提挑战（先确认值不值得做）

先请用户用一句话讲这个想法（调用时已给就复述确认）；再走结论循环把三点问破，别接受第一版说法就往下：

1. **本质问题**（第一性原理）：剥离形态，这个产品要解决的"本质问题"是什么？它帮用户达成什么 job？
2. **换框架**（对抗）：换个视角看这个问题，会不会有更简单、更有力、或完全不同的解法？（如"工具"→"服务"、"产品"→"社区"）
3. **什么都不做**（对抗）：如果今天不做，目标用户的痛点还在吗？是真实需求还是想象的？有多痛、多频繁？

→ 结论写进 sense.md「一、前提挑战」：采纳/否决哪个框架、为什么；不做时痛点是否仍在。

### 1.2 用户与问题（从人出发）

1. **目标用户**（ask+启发）：核心用户是谁？现在怎么解决这个问题？（现状 = 隐藏竞品）
   - 对抗：这是真实人群还是画出来的画像？谁最痛、最值得先服务？
   - → sense.md「二、目标用户」
2. **用户痛点**（ask+启发+联网）：痛在哪、多痛、多频繁？
   - 启发：给痛点维度（效率/成本/情绪/风险/机会损失……）
   - 联网：搜 `<问题> 用户 抱怨/痛点`，验证有真实呼声还是想象
   - → sense.md「三、用户痛点」
3. **要解决的问题**（ask+收敛）：一句清晰的问题陈述
   - 对抗：这句话能证伪吗？产品做出来，怎么知道问题解决了？
   - → sense.md「四、要解决的问题」

### 1.3 方案与本质（怎么做、是什么）

1. **解决方案**（ask+对抗+联网）：打算怎么解决？
   - 第一性原理：达成用户 job 的最短路径是什么？方案绕远了吗？
   - 对抗：逼出 ≥1 个备选，比较各自代价，别拿第一个答案就写
   - 联网：搜 `<问题> 怎么做/方案`，看是否已有现成做法，避免重复造轮子
   - → sense.md「五、解决方案」
2. **产品品类**（ask+启发+联网）：这属于哪类产品？
   - 启发：给品类候选（工具/社区/服务/平台/内容……）
   - 联网：搜 `<品类> 产品 有哪些`，品类真实存在吗？已被占满吗？
   - → sense.md「六、产品品类」
3. **一句话定位**（ask+收敛）：用一句话说清"这是什么、给谁、带来什么"
   - 对抗：这句话换到竞品身上也成立吗？成立就是没定位
   - → sense.md「七、一句话定位」

### 1.4 旅程与落地（用户怎么用、在哪用）

1. **核心用户旅程**（ask+启发）：用户从进入到获得价值的几步
   - 启发：给常见旅程骨架（发现→上手→核心动作→获得价值→回流）
   - → sense.md「八、核心用户旅程」
2. **核心主脉络（28 定律）**（ask+对抗）：承载 80% 价值的 20% 核心功能
   - 对抗：砍到只剩这 20%，用户还能获得价值吗？砍不掉的才是主脉络
   - → sense.md「九、核心主脉络」
3. **平台形态**（ask，AskUserQuestion 单选）：web / H5 / 小程序 / 手机App / 客户端 —— **结构性决策，必须 push 到拍板，不许兜底带过**
   - 启发：给每个平台的取舍框架——web/H5（零安装易传播、留存弱）、小程序（微信生态低门槛、体验受限且数据归平台）、手机App（体验/推送最强、下载门槛高）、客户端（能力最强、分发难）
   - 第一性原理：把问题从"哪个平台"换成"**哪个平台才能让核心体验与竞争力成立**"——推送=App、微信社交裂变=小程序、专业桌面工具=客户端；先想核心体验绑在哪个平台
   - 对抗：拆开你的纠结点（成本/传播/体验/开发），逐项逼决策，别整体悬着
   - 联网：搜同类产品分别选了哪个平台、为什么——竞品的平台选择就是竞争信号
   - 拍板：给出明确推荐 + 理由，要求用户定；仍犹豫就按拆出的纠结点逐个逼，**不许以"待定"带过**
   - → sense.md「十、产品形态（平台）」只填拍板结果

### 1.5 竞争与差异（凭什么）

1. **竞品**（ask+对抗+联网）：市面上相似的产品？各自怎样？
   - 对抗：它做得好不好？有没有查到你设想重叠的玩家？
   - 联网：搜 `<品类> 竞品` 或 `<category> landscape <今年>`；对每个已提名竞品至少查证一件：做的是什么、优缺点
   - → sense.md「十一、竞品分析」（区分【用户认知】/【查证所得】，附来源）
2. **差异点**（ask+对抗+联网）：你希望做到不一样的是什么？
   - 对抗：凭什么是你——一个周末能抄走的差异不是差异（要有防御性）；为什么是现在，早一年/晚一年会怎样？
   - 联网：搜 `<差异点> 产品`，验证"差异化"是不是真差异、是否已有产品在做
   - → sense.md「十二、差异点」

### 1.6 价值与愿景（相信什么、做多大）

1. **产品理念**（ask+收敛）：这个产品相信什么？存在的理由、核心主张
   - 启发：把前面环节的结论收敛成一句理念（不是口号，是立场）
   - → sense.md「十三、产品理念」
2. **10x 愿景**（ask+启发）：如果做到极致，12 个月后这个产品长什么样？
   - 启发：给"更夸张但可想象"的版本，帮用户跳出今天的形态
   - → sense.md「十四、10x 愿景」

### 1.7 商业与风险（怎么活、怎么死）

1. **成功指标**（ask+第一性原理）：怎么衡量做对了？
   - 第一性原理：指标必须能证伪"问题被解决了"，定 1 个北极星 + 2-3 个辅助
   - → sense.md「十五、成功指标（北极星）」
2. **商业模式**（ask）：怎么活下来？（订阅/增值/其他，或标"待定"）
   - → sense.md「十六、商业模式 / 变现路径」
3. **逆向问题 / 风险依赖**（ask+对抗）：什么会让它失败？
   - 对抗：Munger 逆向——先想怎么失败，再倒推要防什么；外部依赖、假设不成立的后果
   - → sense.md「十七、逆向问题 / 风险与依赖」

### 1.8 完成度门禁（MECE 自检，缺就补一轮）

收敛成摘要前，用 MECE 过一遍完整性，缺就补问：
- **用户/问题**：目标用户、痛点、问题陈述齐了吗？
- **方案/本质**：解决方案（含备选）、品类、定位齐了吗？
- **旅程/落地**：用户旅程、主脉络齐了吗？平台**已拍板**了吗？（平台是结构性决策，不许用（假设）顶替）
- **竞争/价值**：竞品查证过、差异有防御性、理念、愿景齐了吗？
- **商业/风险**：指标、变现、逆向/依赖齐了吗？
- **标注**：每项都标了【事实】/【假设】/【待定】吗？假设必须可见
- **素材**：现在去 demo 3 页（Phase 2），主脉络 / 用户旅程 / 核心功能各对应得上哪页？

有缺就补一轮 grill，再进入确认。
